1. Bối cảnh bài toán

Xây dựng phần còn thiếu cho Hệ thống Quản lý Mượn Sách Thư viện (Library Management System) theo kiến trúc Microservices gồm các dịch vụ sau:

Service Port Chức năng / Ý nghĩa
eureka-server 8761 Service Registry - Quản lý việc đăng ký và phát hiện dịch vụ (Cung cấp sẵn)
api-gateway 8080 API Gateway - Cổng truy cập chung và định tuyến request (Cung cấp sẵn)
book-service 8081 Quản lý thông tin sách, hỗ trợ Redis Caching để tối ưu tra cứu
borrow-service 8082 Tiếp nhận yêu cầu mượn sách, gọi book-service qua OpenFeign, lưu phiếu mượn và phát sự kiện Kafka
notification-service 8083 Lắng nghe sự kiện Kafka và gửi thông báo email xác nhận mượn sách

2. Thông tin API & Quy ước dữ liệu

Danh sách Endpoint chính (gọi qua Gateway Port 8080):

Chức năng HTTP Method Endpoint
Tra cứu thông tin sách theo ID GET /api/v1/books/{id}
Tạo phiếu mượn sách POST /api/v1/borrows

Sample Request tạo phiếu mượn sách:

POST http://localhost:8080/api/v1/borrows
Content-Type: application/json

{
  "studentId": "SV12345",
  "studentEmail": "nguyenvana@gmail.com",
  "bookId": 1
}

3. Chi tiết các phần bài thi

PHẦN 1: Borrow Service (60 điểm)

Thí sinh mở file BorrowServiceImpl.java và KafkaProducerService.java để viết code:

  • Gọi Book Service: Sử dụng BookClient để lấy chi tiết thông tin sách theo bookId.
    • Nếu BookClient trả về null (do book-service bị sập), ném exception IllegalStateException("Dich vu Book Service hien khong kha dung") -> Trả về HTTP 503.
    • Nếu availableQuantity <= 0, ném exception IllegalArgumentException("Sach da het, khong the muon") -> Trả về HTTP 400.
  • Lưu thông tin mượn: Khởi tạo entity BorrowRecord với trạng thái "BORROWED", ngày mượn là thời gian hiện tại và lưu vào Database.
  • Phát sự kiện Kafka: Hoàn thiện phương thức trong KafkaProducerService.java để phát chuỗi studentEmail tới Kafka topic borrow-created.
  • Response: Trả về BorrowResponse với HTTP Status 201 Created.

PHẦN 2: Book Service (25 điểm)

Thí sinh mở file BookServiceImpl.java để hoàn thiện cơ chế Caching:

  • Áp dụng annotation @Cacheable trên phương thức getBookById(Long id).
  • Đặt tên cache là "books" và cache key là #id.
  • Lần truy vấn đầu tiên sẽ lấy từ H2 Database và lưu vào Redis. Các lần tra cứu tiếp theo với cùng ID sẽ đọc dữ liệu từ Redis.

PHẦN 3: Notification Service (15 điểm)

Thí sinh mở file NotificationConsumer.java để viết mã cho Kafka Consumer:

  • Khai báo annotation @KafkaListener để lắng nghe sự kiện từ topic borrow-created.
  • Đọc thông tin payload studentEmail và truyền vào phương thức notificationService.sendEmailNotification(...).
